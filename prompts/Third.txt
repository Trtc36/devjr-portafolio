Actúa como un arquitecto de software senior con experiencia en frontend engineering, design systems y product design.

Tienes un proyecto Next.js (App Router) que ya cuenta con:
- estructura modular (features-based)
- páginas funcionales (home, projects, blog, about, contact)
- dark mode y light mode
- UI base correcta pero con problemas de profundidad visual, colorimetría y comunicación de valor

Tu tarea NO es rehacer el proyecto.
Tu tarea es REFINARLO a nivel producto profesional.

---

## 🎯 OBJETIVO PRINCIPAL

Transformar la UI actual en una experiencia:
- visualmente jerárquica
- con profundidad (layering real)
- con identidad clara (no genérica)
- alineada a un perfil de ingeniería senior (no junior, no template)

Y mejorar la comunicación del portafolio para que transmita:
- criterio técnico
- enfoque en sistemas
- pensamiento arquitectónico
- orientación a producto

---

# 🧱 PARTE 1 — SISTEMA VISUAL (CRÍTICO)

## 1. Implementar un design system real basado en tokens

Define tokens de color para ambos modos:

### Dark mode
- background (base)
- surface (cards)
- elevated (hover/focus)
- border
- text primary
- text secondary
- accent

### Light mode
- background
- surface
- elevated
- border
- text primary
- text secondary
- accent

NO usar valores arbitrarios en componentes.
Centralizar en variables o theme config.

---

## 2. Resolver el problema de “UI plana”

Actualmente la UI es visualmente plana.

Debes introducir:
- jerarquía de capas (background / surface / elevated)
- sombras suaves en light mode
- diferencias reales entre contenedores
- separación visual clara entre secciones

Cada componente debe pertenecer claramente a una capa visual.

---

## 3. Mejorar contraste sin romper elegancia

Evitar:
- contrastes excesivos
- fondos totalmente negros o totalmente blancos sin matices

Lograr:
- contraste suficiente para legibilidad
- diferenciación clara entre bloques
- consistencia entre dark y light mode

---

## 4. Introducir color de acento coherente

Agregar un color de acento único y consistente que se use en:
- botones principales
- hover states
- links
- elementos interactivos

Debe sentirse:
- técnico
- moderno
- sobrio

Evitar colores saturados tipo marketing.

---

# 🧠 PARTE 2 — JERARQUÍA Y UX

## 1. Mejorar legibilidad estructural

Asegurar:
- separación clara entre secciones
- títulos con peso visual real
- subtítulos diferenciados
- contenido escaneable

Evitar bloques que parezcan “texto plano”.

---

## 2. Mejorar interacción en cards

Agregar:
- hover states claros
- cambios sutiles de elevación
- feedback visual en interacción

Las cards deben sentirse “clickeables” y vivas.

---

## 3. Resolver problema del footer

El footer actualmente se desplaza hacia arriba cuando hay poco contenido.

Corregir layout global usando:
- flex column layout
- min-h-screen
- main con flex-grow

El footer SIEMPRE debe quedarse abajo.

---

# 🧠 PARTE 3 — COMUNICACIÓN (MUY IMPORTANTE)

## 1. Ajustar el contenido del Home (Resumen)

El home NO debe enfocarse en tecnologías.

Eliminar del resumen:
- stacks específicos (ASP.NET, PostgreSQL, etc.)

Reemplazar por:
- enfoque de ingeniería
- tipo de sistemas construidos
- filosofía de trabajo
- valor entregado

Ejemplo de enfoque:
“sistemas backend orientados a dominio”
“arquitectura para operaciones reales”
“software diseñado para ser mantenible y observable”

---

## 2. Mantener tecnologías SOLO en proyectos

Las tecnologías deben:
- quedarse en la sección de proyectos
- dar contexto técnico
- no dominar la narrativa

---

## 3. Reforzar posicionamiento profesional

Todo el sitio debe comunicar:

- ingeniería > desarrollo
- sistemas > features
- producto > código

Evitar tono de portafolio junior.

---

# 🧱 PARTE 4 — CONSISTENCIA

Asegurar:

- spacing consistente
- paddings coherentes
- grid alineado
- tipografía uniforme
- mismo lenguaje visual en todas las páginas

---

# 🧠 PARTE 5 — RESTRICCIONES

NO hacer:
- rediseño completo
- cambios de estructura de carpetas
- cambios de routing
- agregar librerías innecesarias

SÍ hacer:
- refactor visual
- mejora de tokens
- ajuste de componentes existentes
- mejora UX/UI

---

# 🎯 RESULTADO ESPERADO

Un portafolio que:

- se vea como producto real, no template
- tenga profundidad visual clara
- sea cómodo de navegar
- transmita criterio de ingeniería senior
- sea coherente en dark y light mode
